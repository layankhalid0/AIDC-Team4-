# W5D2 – Alerts and Service Report

## Overview

This lab focused on configuring Grafana alerting for the Team 4 model-serving service, validating webhook notifications, and reporting an observed service result against a documented SLO.

The monitored service is an OpenAI-compatible vLLM endpoint serving:

**Model:** `Qwen/Qwen2.5-1.5B-Instruct-AWQ`

**Namespace:** `team`

---

## Service Alert

A Grafana-managed alert rule named **Team service alert** was created using the p95 Time to First Token (TTFT) indicator documented in W5D1.

### SLO

- **Indicator:** p95 Time to First Token (TTFT)
- **Target:** `<= 0.10 seconds`
- **Prometheus query window:** `5m`
- **Proposed SLO window:** `30 minutes`
- **Alert condition:** p95 TTFT `> 0.10 seconds`
- **Evaluation interval:** `1 minute`
- **Pending period:** `1 minute`

### PromQL

```promql
histogram_quantile(
  0.95,
  sum by (le) (
    rate(vllm:time_to_first_token_seconds_bucket[5m])
  )
)
```

Artificial chat traffic was generated using `traffic.py` to provide recent observations for the service metric.

The observed p95 TTFT during the test was:

```text
0.03881 seconds
```

Approximately:

```text
38.81 ms
```

This was below the proposed `0.10 s` target during the observed workload.

Because the workload did not cover the full proposed 30-minute SLO window, the service report records the conclusion as **insufficient evidence** rather than claiming full SLO compliance.

## Notification Test

A separate Grafana-managed rule named **Lab notification test** was used to verify the alert notification path.

The artificial PromQL signal was:

```promql
vector(time() % 120 < bool 60)
```

The rule used:

- Evaluation interval: `10s`
- Pending period: `20s`
- Contact point: `Lab inbox`
- Group wait: `0s`
- Group interval: `10s`
- Repeat interval: `1h`

The webhook receiver successfully recorded both alert states:

```text
firing  -> 2026-09-14 08:56:25 UTC
resolved -> 2026-09-14 09:10:05 UTC
```

After recovery was confirmed, **Lab notification test** was paused while **Team service alert** remained enabled.

## Measurement Limitations

The observed TTFT measurement was collected during a short artificial workload and does not cover the full proposed 30-minute SLO window.

The metric measures server-side time to first token and does not include network latency, client-side latency, or model-output quality. A longer representative workload is required before making a stronger SLO compliance claim.
